# ADR-0014 — Passage à Python 3.13

- **Statut** : accepté
- **Date** : 2026-11-22

## Contexte

Le projet visait Python ≥ 3.12. L'expérience TLS (ADR-0012) a montré un gain concret à passer en 3.13 :
`ssl.SSLObject.get_verified_chain()`, disponible à partir de cette version, donne la **chaîne vérifiée complète** du
certificat client, alors qu'en 3.12 seul le certificat feuille est accessible. Python 3.13 est stable et
largement distribué ; 3.14 est sorti depuis.

## Décision

- `requires-python = ">=3.13"`, `.python-version` à `3.13`, image de base `python:3.13-slim`.
- CI sur Python **3.13 et 3.14**.
- Le code peut utiliser librement les nouveautés de 3.13, en particulier `get_verified_chain()` dans le protocole
  TLS du lanceur.

## Alternatives considérées

- **Rester en 3.12** : possible (le certificat feuille suffit pour EST), mais on se priverait de la chaîne du client
  et on retarderait une montée de version inévitable.

## Conséquences

- `uv.lock` est régénéré pour 3.13 ; les dépendances sont vérifiées sur 3.13 et 3.14 en CI.
- Les environnements de développement doivent disposer de Python 3.13 (uv l'installe au besoin).
